# 参考截面自动隧道生成工具

> 日期：2026-07-26  
> 适用：NebulaeCraft / Minecraft Forge 1.12.2 / Java 8

## 物品与标记

- `nebulaecraft:autogen_marker`：跨栏式方向标记，橙色箭头表示方向。放置后可空手右键旋转。
- `nebulaecraft:autogen_wand`：依次右键起点和终点标记以记录选区；潜行右键空气可清除选区。
- 两个箭头必须相向。标记所在方块会成为中央道床方块，生成完成后由道床替换，执行撤销时恢复。

## 指令

完整指令名为 `/nebulaetunnel`，可缩写为 `/ntunnel`，需要权限等级 2。

```text
/ntunnel preview <preset> <platformColor> <power> [mirror]
/ntunnel confirm
/ntunnel cancel
/ntunnel status
/ntunnel undo
/ntunnel reload
/ntunnel clear
```

默认预设仍命名为 `metro_6x5`，以兼容已有指令和配置。供电参数：

- `none`
- `catenary`
- `thirdrail_white`
- `thirdrail_yellow`

示例：

```text
/ntunnel preview metro_6x5 cyan catenary
/ntunnel preview metro_6x5 yellow thirdrail_yellow mirror
/ntunnel confirm
```

平台颜色支持 Railcraft 的 16 色英文名，额外接受 `silver`、`lightGray`、`lightBlue` 别名。

## 默认断面与材料

- 断面固定为 7×7；从上至下逐层为：
  - `7×强化混凝土`
  - `2×强化混凝土 + 强化混凝土上台阶(subtype1) + 钢性接触网 + 强化混凝土上台阶(subtype1) + 2×强化混凝土`
  - `强化混凝土 + 5×空气 + 强化混凝土`
  - `强化混凝土垂直台阶 + 5×空气 + 强化混凝土垂直台阶`（连续两层）
  - `强化混凝土 + 2×空气 + 强化轨道 + 2×空气 + 强化混凝土`
  - `2×强化混凝土 + 44:0 + 43:8 + 44:0 + 2×强化混凝土`
- 弯道相邻截面的空气区域取并集，避免衬砌在曲线内部形成横向立柱；平台、第三轨和隧道灯作为可选设施占用净空格，但不再替换结构衬砌。
- 方格化曲线发生一格横向换位时，完整七层都使用旋转后的 3×8 专用过渡模板：`43:8` 中央道床和钢性接触网槽按 `1格 → 2格 → 1格` 斜向换位，`44:0` 与 subtype1 台阶分别在两侧补齐；顶板扩宽为 8 格，普通净空层扩为两侧外墙包住 6 格净空，两层垂直台阶同步移动到过渡外缘，避免相邻普通断面互相覆盖形成收窄、缺角和内部墙柱。
- 连续弯道由多组一格横移首尾拼接；90° 弯道中部的断面主轴从 X 切换到 Z 时，只保留一套不重叠的格化结构模板，被去重模板不再重复放置完整侧墙、地板或顶板。最终墙面仍由合并净空的真实外缘统一重建；垂直强化混凝土台阶的朝向不再按换轴轮廓长度均分，而是逐格采用最近中心曲线位置的解析切线。
- 上述去重只限制完整侧墙、地板和顶板模板；被去重的新轴候选仍把实际拥有的 `43:8/44:0`、对应净空缓冲及接触网凹槽语义并入最终结构，避免新轴方向的道床被旧轴墙体覆盖。
- 地板、侧墙、接触网凹槽的默认混凝土层与最外层顶板统一从最终合并净空推导，不再让后两层只依赖被保留的完整断面模板。每个最终净空格都会取得默认凹槽外层和顶板，显式的凹槽空气、水平台阶、刚性接触网及坡道抬高层再按既有优先级覆盖；因此换轴处即使去重一套重叠的 3×8 实体模板，其道床扩展出来的真实净空仍一定具有封闭顶部。
- 普通外轮廓格在中间两层始终使用垂直强化混凝土台阶。生成器保留每个方格化中心轨道格对应的五次 Hermite 曲线参数，并直接计算该点的解析切线：当 `|dx/dt| >= |dz/dt|`（切线更接近 Minecraft X 轴）时，垂直台阶使用 `facing=north/south`；当 `|dz/dt| > |dx/dt|`（切线更接近 North/South 轴）时使用 `facing=east/west`。朝向的正负方向选择指向中心线路的一侧。该规则会在最终结构完成后统一应用于全部垂直台阶，包括阶梯内角、换轴中心和模板残留格，不再受方格锯齿的瞬时方向或旧轴迟滞阈值影响。
- 同一解析切线也是隧道内其他旋转方块的统一方向来源。隧道灯以及直线/坡线第三轨的 `facing` 表示线路侧向，因此使用与垂直台阶相同的法线轴；直线、支撑和坡线刚性接触网的模型轴则与切线轴平行。坡线仍结合真实高低端选择正反方向。Railcraft 弯轨、刚性接触网斜线和第三轨斜线必须连接方格路线中两个实际相邻方向，因而保留连接拓扑决定的弯角/斜线象限；解析切线负责它们所属断面、侧向及进入/离开斜线前后的直线朝向，不能用单一卡迪纳尔轴替代实际连接。
- 墙后接缝按最终净空和最终正交墙边界推导，不再依赖某套 3×8 模板的固定候选坐标：一个外角只有在连接它与某个对角净空格的两个正交中间格都是真实墙格时，才补完整强化混凝土背衬。该条件能覆盖连续换位及 X/Z 换轴新增的缝隙，同时排除仅仅对角邻接净空的内侧格，不会重新生成侵入隧道的混凝土立柱。
- 整块衬砌：`railcraft:reinforced_concrete` meta 8（light gray）。
- 接触网槽两侧固定使用 NebulaeCraft 水平强化混凝土台阶 `subtype1`；中部两层侧墙固定使用朝外贴墙的垂直强化混凝土台阶。
- 强化轨道处于一格高差的下端、使用坡道模型时，该格改用 7×8 坡道专用断面；从上至下为：
  - `7×强化混凝土`
  - `2×强化混凝土 + 强化混凝土上台阶(subtype1) + 空气 + 强化混凝土上台阶(subtype1) + 2×强化混凝土`
  - `强化混凝土 + 2×空气 + 钢性接触网斜坡 + 2×空气 + 强化混凝土`
  - `强化混凝土垂直台阶 + 5×空气 + 强化混凝土垂直台阶`（连续三层）
  - `强化混凝土 + 2×空气 + 强化轨道斜坡 + 2×空气 + 强化混凝土`
  - `2×强化混凝土 + 3×43:8 + 2×强化混凝土`
  上端的平轨格仍使用普通断面，并与坡道格抬高一层的顶板自然衔接。
- 统一外轮廓在坡道交界会把同一 XZ 的相邻高度净空视为连续，并在写墙前逐格避让已有净空体积，因此低端断面不会在高端道床前形成横断墙。坡道原模板位于 `clearHeight` 的第三排垂直台阶会在外轮廓重建时保留，并按最终净空方向校正朝向；普通平坡墙仍只有两排。
- 本模组旋转方块不使用原版水平 metadata 顺序。生成器按实际模型显式使用 `N=0、S=1、W=2、E=3`，并分别处理侧贴模型、第三轨内外弯模型及钢性接触网的斜线/坡线方向。
- 中央道床：旧 ID `43:8`，即 `minecraft:double_stone_slab` meta 8。
- 左右道床：旧 ID `44:0`，即 `minecraft:stone_slab` meta 0。
- 轨道：`railcraft:track_flex_reinforced`；配置读取同时兼容 `railcraft:reinforced_track` 和 `railcraft:track_reinforced`。
- Railcraft 弹性轨道首次放入世界时会按当时已经存在的邻轨自动改形。生成器会先完成整条轨道放置，再按路线计算结果执行一次不重复记录撤销数据的定向复写，保证连续弯轨及 90° 中段不会因分批生成顺序而断开。
- 弯道路基先于平台和墙面按整条轨道路网规划：每个轨道格固定使用 `43:8`，每段前后连接方向的两侧邻格组成 `44:0` 带；真正的坡轨格两侧仍使用 `43:8`，3×8 过渡模板额外扩宽的 `43:8/44:0` 也进入同一占位集合。若同一条 `44:0` 侧带在格化斜线处仅以角相接，生成器会在两个正交肘点中排除属于 `43:8` 中央道床的一个，并补入唯一的外侧肘点，直至每条侧带都以共享边四向连通；它不会强制两侧数量相等，例如 200 格的半径 100 弧线应保持外侧 202 格、内侧 198 格。全部道床格随后并入净空再提取墙面，因此垂直台阶墙列不会与 `43:8/44:0` 共用坐标。
- 全部 3×8 过渡候选（包括换轴时被去重的候选）都会参与道床占位；最终占位还向四个水平方向扩张一格作为混凝土地板与净空缓冲，路线开放端之外不扩张。因此垂直台阶墙列既不会与 `43:8/44:0` 共用坐标，也不会直接贴住侧道床。
- 道床净空缓冲在一格坡道交界处不会跨入同一 XZ 柱中高一层或低一层的相邻道床；因此高端道床的缓冲不会在低端三格 `43:8` 上方生成强化混凝土，低端缓冲也不会在高端道床下方留下隧道外的三格强化混凝土。同层曲线及 3×8 换位仍保留完整的四向缓冲。
- 平台默认位于起点至终点方向的左侧，第三轨位于右侧；`mirror` 会交换两侧。方格化曲线发生一格横向换位时，先计算每个过渡的新平台锚点；X/Z 轴切中被去重的结构模板仍保留自己的平台锚点。删除道床上方的无效旧格后，只有尚未被现有平台 8 邻接连通的相邻锚点才补斜线桥，避免在本来正常的过渡旁再铺一条平台。最终单格宽平台线在墙面生成前并入净空并取得完整强化混凝土基层，所有落在最终 `43:8/44:0` 上方的旧平台格统一删除，避免断线、错位和压占侧道床。
- 平台补桥不再使用唯一的整数取整斜线，而是在路线顺序相邻的过渡锚点局部包围盒内执行 8 邻接最短路。桥格必须已经位于最终净空、距线路 2–3 格、不属于道床、不越过开放端，也不能覆盖轨道或第三轨等设施；因此可在两种等长斜线相位中选择不压 `43:8/44:0` 的一条，而不会跨接远处弯道。
- 第三轨坡道模型仅放置在真正使用上坡轨道状态的低端切面；相邻高端平轨切面恢复普通第三轨。
- 第三轨支架直接以 `thirdRailSupportSpacing` 作为有效线路长度索引周期；默认值为 3，在有效索引 `0, 3, 6...` 使用对应颜色的直线或斜线支架模型，因此两个支架之间保留 2 个长度单位。坡道没有专用支架模型，命中支架索引时保留坡道模型。
- 第三轨先按解析切线法线构造独立的有序侧线，再根据侧线中每个方块的真实前后连接选择 `diagonal_1` / `diagonal_2` 及方向。单格横移位于第三轨一侧时，斜线对锚定在两个轨道转角之前；位于另一侧时，以相反的模型次序和方向锚定在两个转角之后，避免 `diagonal_2` 落到中心轨道坐标而被覆盖。只有 `diagonal_1` 允许替换为斜线支架。
- 解析切线的 X/Z 主轴在弯道中段切换时，内侧第三轨会产生一个压轨候选和一个重复候选，二者从有效侧线中删除；外侧第三轨会产生三格曼哈顿距离的局部缺口，生成器在不经过中心轨道的前提下补入两个连接格。最终内外侧线都按共享边连续，并以实际侧线路径重新计算全部斜线模型，不继承结构模板的去重相位。
- 第三轨支架间距使用有效线路长度计数：相邻的一组 `diagonal_1 + diagonal_2` 合计只计一格。连续 45° 斜线由首尾相接的斜线模型组成，中间不退回按轨道索引推测的普通转角，也不插入额外直线第三轨。
- 隧道灯直接以 `lightSpacing` 作为路线索引周期；默认值为 9，放置索引固定为 `0, 9, 18...`，因此两盏灯之间有 8 格。灯具全部位于金属平台一侧；使用 `mirror` 时与平台同步换边。
- 每盏灯都从轨道中心沿平台侧扫描最终合并净空，放在首个非净空墙格之前的最后一格；连续斜线与 X/Z 换轴处即使外墙相对普通断面移动一格或两格，灯具仍会贴住实际外墙。扫描每前进一步都会按解析切线断面重新取得该横向格的楼层，跨越曲线坡道的高低分界时不会因只检查中心轨道 Y 而提前停在净空中。
- 灯具最终落点属于坡道断面时向上移动一格，以贴合坡道专用断面抬高后的完整侧墙；判断依据是灯具所在的墙前断面，而非同一索引的中心轨道格。
- 接触网支撑件同样直接以 `catenarySupportSpacing` 作为路线索引周期；默认值为 9，目标索引为 `0, 9, 18...`。若目标格是斜线或坡线接触网，则保留该特化模型，并在前后两格内选择最近的直线接触网格放置支撑件；若四个邻近候选均非直线，本次支撑件放置直接跳过。
- 坡线接触网只生成在真正使用上坡轨道状态的低端切面；与其相邻的高端平轨切面使用普通直线接触网。
- 曲线上的一格高差不会再占用方格化横移的入段、横移或出段三条边。若五次 Hermite 高程的取整点落在该 3×8 过渡内，坡步会沿线路低侧移动到最近的切线同轴直线边；正反向选择同一个物理低端坡道格，因此不会把 Railcraft 上坡轨道与水平弯轨合并，也不会把同一套曲线过渡拆到两个高度。
- 隧道各横向格的楼层不再直接继承方格中心点的 Y，而是由每个坡道低端处的解析切线断面划分：以单位切线的点积判定格子位于高侧、低侧或坡道断面内。高低层分界因此是当前曲线切线的垂线，并以 Minecraft 方格阶梯逼近，不会在弯道中退化为固定 X/Z 行。
- 坡道专用七格断面沿上述解析法线逐格取整。曲线坡道两侧墙柱可位于不同的线路纵向坐标，但都使用三格高垂直强化混凝土台阶；接触网凹槽和最外顶板沿同一法线整体抬高一层。直线坡道是该规则的法线恰好平行 X/Z 轴时的特例，既有断面保持不变。
- 旧版配置中的 `clearWidth: 6`、`clearHeight: 5` 以及水平台阶 `subtype0` 会自动迁移为新参考截面；旧的默认设施周期 8 会迁移为直接索引周期 9，并补充默认第三轨支架周期 3，同时写入 `schemaVersion: 5`。

## 配置与安全

首次启动后生成：

```text
config/nebulaecraft/tunnel_presets.json
```

默认限制：路线长度 2048 格、修改 500,000 个方块、每 tick 处理 4096 个方块。预览有效期为 60 秒。修改配置后执行 `/ntunnel reload`。

生成前只显示粒子预览和统计，不修改世界。系统按 tick 分批生成并在世界存档中保存最近一次撤销数据，包括 TileEntity NBT。生成途中执行 `cancel` 会自动回滚已修改部分。

## Railcraft 依赖

Railcraft 是必需依赖。隧道代码通过 Forge 注册表查找 Railcraft 方块，不直接引用 Railcraft Java 类。相邻 Railcraft 源码当前注册的强化轨道 ID 是 `railcraft:track_flex_reinforced`。

开发环境通过 `META-INF/nebulaecraft_at.cfg` 同步公开 Railcraft 所需的 `TileEntity.REGISTRY` 和 `NBTTagList.tagList`。这是因为 ForgeGradle 3 的反混淆运行环境会读取 `run/mods` 中外部 Railcraft JAR 的 Access Transformer，却不会把这些 SRG 字段规则提前应用到开发用 Minecraft 依赖；发布 JAR 清单也包含同一 `FMLAT` 声明。

本项目使用的 ForgeGradle 3 旧版 1.12 管线在 AT 内容变化后可能把仍含 `Side.BUKKIT` 的 joined 中间包放进 `runClient`/`runServer` 类路径，导致 `NetworkRegistry.newChannel` 在模组构造阶段空指针。`prepareDevForgeJar` 会从正确的 `-recomp.jar` 生成项目本地副本，使用 `gradle/nebulaecraft_dev_at.cfg` 中的 MCP 字段名应用同样两条规则；两个运行任务会自动使用该副本。此逻辑仅服务开发运行，不进入发布模组。
