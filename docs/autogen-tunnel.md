# 参考截面自动隧道生成工具

> 日期：2026-07-26  
> 适用：NebulaeCraft / Minecraft Forge 1.12.2 / Java 8

## 物品与标记

- `nebulaecraft:autogen_marker`：跨栏式方向标记，橙色箭头表示方向。放置后可空手右键旋转；选择与碰撞范围按模型原始 `X 7..9、Y 0..13.5、Z 1.5..9` 及当前朝向旋转计算。
- `nebulaecraft:autogen_wand`：依次右键起点和终点标记以记录选区；潜行右键空气可清除选区。
- 两个箭头必须相向。标记所在方块会成为中央道床方块，生成完成后由道床替换，执行撤销时恢复。

## 指令

完整指令名为 `/nebulaetunnel`，可缩写为 `/ntunnel`，需要权限等级 2。

```text
/ntunnel preview <preset> <platformColor> <power> [mirror]
/ntunnel confirm
/ntunnel cancel
/ntunnel status
/ntunnel undo
/ntunnel clear
```

默认预设命名为 `tunnel_metro_1`。供电参数：

- `none`
- `catenary`
- `thirdrail_white`
- `thirdrail_yellow`

示例：

```text
/ntunnel preview tunnel_metro_1 cyan catenary
/ntunnel preview tunnel_metro_1 yellow thirdrail_yellow mirror
/ntunnel confirm
```

平台颜色支持 Railcraft 的 16 色英文名，额外接受 `silver`、`lightGray`、`lightBlue` 别名。

## 默认断面与材料

- 断面固定为 7×7；从上至下逐层为：
  - `7×强化混凝土`
  - `2×强化混凝土 + 强化混凝土上台阶(subtype1) + 钢性接触网 + 强化混凝土上台阶(subtype1) + 2×强化混凝土`
  - `强化混凝土 + 5×空气 + 强化混凝土`
  - `强化混凝土垂直台阶 + 5×空气 + 强化混凝土垂直台阶`（连续两层）
  - `强化混凝土 + 2×空气 + 强化轨道 + 2×空气 + 强化混凝土`
  - `2×强化混凝土 + 44:0 + 43:8 + 44:0 + 2×强化混凝土`
- 弯道相邻截面的空气区域取并集，避免衬砌在曲线内部形成横向立柱；平台、第三轨和隧道灯作为可选设施占用净空格，但不再替换结构衬砌。
- 方格化曲线发生一格横向换位时，完整七层都使用旋转后的 3×8 专用过渡模板：`43:8` 中央道床和钢性接触网槽按 `1格 → 2格 → 1格` 斜向换位，`44:0` 与 subtype1 台阶分别在两侧补齐；顶板扩宽为 8 格，普通净空层扩为两侧外墙包住 6 格净空，两层垂直台阶同步移动到过渡外缘，避免相邻普通断面互相覆盖形成收窄、缺角和内部墙柱。
- 连续弯道由多组一格横移首尾拼接；90° 弯道中部的断面主轴从 X 切换到 Z 时，只保留一套不重叠的格化结构模板，被去重模板不再重复放置完整侧墙、地板或顶板。最终墙面仍由合并净空的真实外缘统一重建；垂直强化混凝土台阶的朝向不再按换轴轮廓长度均分，而是逐格采用最近中心曲线位置的解析切线。
- 上述去重只限制完整侧墙、地板和顶板模板；被去重的新轴候选仍把实际拥有的 `43:8/44:0`、对应净空缓冲及接触网凹槽语义并入最终结构，避免新轴方向的道床被旧轴墙体覆盖。
- 地板、侧墙、接触网凹槽的默认混凝土层与最外层顶板统一从最终合并净空推导，不再让后两层只依赖被保留的完整断面模板。每个最终净空格都会取得默认凹槽外层和顶板，显式的凹槽空气、水平台阶、刚性接触网及坡道抬高层再按既有优先级覆盖；因此换轴处即使去重一套重叠的 3×8 实体模板，其道床扩展出来的真实净空仍一定具有封闭顶部。
- 普通外轮廓格在中间两层始终使用垂直强化混凝土台阶。生成器保留每个方格化中心轨道格对应的五次 Hermite 曲线参数，并直接计算该点的解析切线：当 `|dx/dt| >= |dz/dt|`（切线更接近 Minecraft X 轴）时，垂直台阶使用 `facing=north/south`；当 `|dz/dt| > |dx/dt|`（切线更接近 North/South 轴）时使用 `facing=east/west`。朝向的正负方向选择指向中心线路的一侧。该规则会在最终结构完成后统一应用于全部垂直台阶，包括阶梯内角、换轴中心和模板残留格，不再受方格锯齿的瞬时方向或旧轴迟滞阈值影响。
- 同一解析切线也是隧道内其他旋转方块的统一方向来源。隧道灯以及直线/坡线第三轨的 `facing` 表示线路侧向，因此使用与垂直台阶相同的法线轴；直线、支撑和坡线刚性接触网的模型轴则与切线轴平行。坡线仍结合真实高低端选择正反方向。Railcraft 弯轨、刚性接触网斜线和第三轨斜线必须连接方格路线中两个实际相邻方向，因而保留连接拓扑决定的弯角/斜线象限；解析切线负责它们所属断面、侧向及进入/离开斜线前后的直线朝向，不能用单一卡迪纳尔轴替代实际连接。
- 墙后接缝按最终净空和最终正交墙边界推导，不再依赖某套 3×8 模板的固定候选坐标：一个外角只有在连接它与某个对角净空格的两个正交中间格都是真实墙格时，才补完整强化混凝土背衬。该条件能覆盖连续换位及 X/Z 换轴新增的缝隙，同时排除仅仅对角邻接净空的内侧格，不会重新生成侵入隧道的混凝土立柱。
- 整块衬砌：`railcraft:reinforced_concrete` meta 8（light gray）。
- 接触网槽两侧固定使用 NebulaeCraft 水平强化混凝土台阶 `subtype1`；中部两层侧墙固定使用朝外贴墙的垂直强化混凝土台阶。
- 强化轨道处于一格高差的下端、使用坡道模型时，该格改用 7×8 坡道专用断面；从上至下为：
  - `7×强化混凝土`
  - `2×强化混凝土 + 强化混凝土上台阶(subtype1) + 空气 + 强化混凝土上台阶(subtype1) + 2×强化混凝土`
  - `强化混凝土 + 2×空气 + 钢性接触网斜坡 + 2×空气 + 强化混凝土`
  - `强化混凝土垂直台阶 + 5×空气 + 强化混凝土垂直台阶`（连续三层）
  - `强化混凝土 + 2×空气 + 强化轨道斜坡 + 2×空气 + 强化混凝土`
  - `2×强化混凝土 + 3×43:8 + 2×强化混凝土`
  上端的平轨格仍使用普通断面，并与坡道格抬高一层的顶板自然衔接。
- 统一外轮廓在坡道交界会把同一 XZ 的相邻高度净空视为连续，并在写墙前逐格避让已有净空体积，因此低端断面不会在高端道床前形成横断墙。坡道原模板位于 `clearHeight` 的第三排垂直台阶会在外轮廓重建时保留，并按最终净空方向校正朝向；普通平坡墙仍只有两排。墙列只有在解析断面属于坡轨且墙脚本身也处于该坡轨的低层时才使用抬高顶板；若高侧墙的 X/Z 投影更接近低侧坡轨，它仍按自身高层的普通断面封顶，墙后外角背衬也不会被连带抬高。
- 本模组旋转方块不使用原版水平 metadata 顺序。生成器按实际模型显式使用 `N=0、S=1、W=2、E=3`，并分别处理侧贴模型、第三轨内外弯模型及钢性接触网的斜线/坡线方向。
- 中央道床：旧 ID `43:8`，即 `minecraft:double_stone_slab` meta 8。
- 左右道床：旧 ID `44:0`，即 `minecraft:stone_slab` meta 0。
- 轨道：`railcraft:track_flex_reinforced`；方块解析仍兼容旧 ID `railcraft:reinforced_track` 和 `railcraft:track_reinforced`。
- Railcraft 弹性轨道首次放入世界时会按当时已经存在的邻轨自动改形。生成器会先完成整条轨道放置，再按路线计算结果执行一次不重复记录撤销数据的定向复写，保证连续弯轨及 90° 中段不会因分批生成顺序而断开。
- 弯道路基先于平台和墙面按整条轨道路网规划：每个轨道格固定使用 `43:8`，每段前后连接方向的两侧邻格组成 `44:0` 带；真正的坡轨格两侧仍使用 `43:8`，3×8 过渡模板额外扩宽的 `43:8/44:0` 也进入同一占位集合。若同一条 `44:0` 侧带在格化斜线处仅以角相接，生成器会在两个正交肘点中排除属于 `43:8` 中央道床的一个，并补入唯一的外侧肘点，直至每条侧带都以共享边四向连通；它不会强制两侧数量相等，例如 200 格的半径 100 弧线应保持外侧 202 格、内侧 198 格。全部道床格随后并入净空再提取墙面，因此垂直台阶墙列不会与 `43:8/44:0` 共用坐标。
- 全部 3×8 过渡候选（包括换轴时被去重的候选）都会参与道床占位；最终占位还向四个水平方向扩张一格作为混凝土地板与净空缓冲，路线开放端之外不扩张。因此垂直台阶墙列既不会与 `43:8/44:0` 共用坐标，也不会直接贴住侧道床。
- 道床净空缓冲在一格坡道交界处不会跨入同一 XZ 柱中高一层或低一层的相邻道床；因此高端道床的缓冲不会在低端三格 `43:8` 上方生成强化混凝土，低端缓冲也不会在高端道床下方留下隧道外的三格强化混凝土。同层曲线及 3×8 换位仍保留完整的四向缓冲。
- 平台默认位于起点至终点方向的左侧，第三轨位于右侧；`mirror` 会交换两侧。方格化曲线发生一格横向换位时，先计算每个过渡的新平台锚点；X/Z 轴切中被去重的结构模板仍保留自己的平台锚点。删除道床上方的无效旧格后，只有尚未被现有平台 8 邻接连通的相邻锚点才补斜线桥，避免在本来正常的过渡旁再铺一条平台。最终单格宽平台线在墙面生成前并入净空并取得完整强化混凝土基层，所有落在最终 `43:8/44:0` 上方的旧平台格统一删除，避免断线、错位和压占侧道床。
- 平台补桥不再使用唯一的整数取整斜线，而是在路线顺序相邻的过渡锚点局部包围盒内执行 8 邻接最短路。桥格必须已经位于最终净空、距线路 2–3 格、不属于道床、不越过开放端，也不能覆盖轨道或第三轨等设施；因此可在两种等长斜线相位中选择不压 `43:8/44:0` 的一条，而不会跨接远处弯道。
- 跨层弯道的平台过渡锚点不直接继承中心路线格的 Y；待删除锚点和新增锚点都以自身 X/Z 经 `GradeLayout.floorAt` 取得解析坡面楼层，再上移一格。因此平台侧格跨过高低分界时，其高度与最终净空、道床和普通平台线使用同一分层规则。
- 第三轨坡道模型仅放置在真正使用上坡轨道状态的低端切面；相邻高端平轨切面恢复普通第三轨。
- 第三轨支架直接以 `thirdRailSupportSpacing` 作为有效线路长度索引周期；默认值为 3，在有效索引 `0, 3, 6...` 使用对应颜色的直线或斜线支架模型，因此两个支架之间保留 2 个长度单位。坡道没有专用支架模型，命中支架索引时保留坡道模型。
- 第三轨先按解析切线法线构造独立的有序侧线，再根据侧线中每个方块的真实前后连接选择 `diagonal_1` / `diagonal_2` 及方向。单格横移位于第三轨一侧时，斜线对锚定在两个轨道转角之前；位于另一侧时，以相反的模型次序和方向锚定在两个转角之后，避免 `diagonal_2` 落到中心轨道坐标而被覆盖。只有 `diagonal_1` 允许替换为斜线支架。
- 解析切线的 X/Z 主轴在弯道中段切换时，内侧第三轨会产生一个压轨候选和一个重复候选，二者从有效侧线中删除；外侧第三轨会产生三格曼哈顿距离的局部缺口，生成器在不经过中心轨道的前提下补入两个连接格。最终内外侧线都按共享边连续，并以实际侧线路径重新计算全部斜线模型，不继承结构模板的去重相位。
- 第三轨支架间距使用有效线路长度计数：相邻的一组 `diagonal_1 + diagonal_2` 合计只计一格。连续 45° 斜线由首尾相接的斜线模型组成，中间不退回按轨道索引推测的普通转角，也不插入额外直线第三轨。
- 隧道灯直接以 `lightSpacing` 作为路线索引周期；默认值为 9，放置索引固定为 `0, 9, 18...`，因此两盏灯之间有 8 格。灯具全部位于金属平台一侧；使用 `mirror` 时与平台同步换边。
- 每盏灯都从轨道中心沿平台侧扫描最终合并净空，放在首个非净空墙格之前的最后一格；连续斜线与 X/Z 换轴处即使外墙相对普通断面移动一格或两格，灯具仍会贴住实际外墙。扫描每前进一步都会按解析切线断面重新取得该横向格的楼层，跨越曲线坡道的高低分界时不会因只检查中心轨道 Y 而提前停在净空中。
- 灯具最终落点属于坡道断面时向上移动一格，以贴合坡道专用断面抬高后的完整侧墙；判断依据是灯具所在的墙前断面，而非同一索引的中心轨道格。
- 接触网支撑件同样直接以 `catenarySupportSpacing` 作为路线索引周期；默认值为 9，目标索引为 `0, 9, 18...`。若目标格是斜线或坡线接触网，则保留该特化模型，并在前后两格内选择最近的直线接触网格放置支撑件；若四个邻近候选均非直线，本次支撑件放置直接跳过。
- 坡线接触网只生成在真正使用上坡轨道状态的低端切面；与其相邻的高端平轨切面使用普通直线接触网。
- 曲线上的一格高差不会占用方格化横移边，坡轨低端也必须是能连接前后轨道的直轨格。为避免连续弯道把过长路段全部排除，3×8 过渡现允许在已完成横移后的低侧外边接入坡道：入段、中间横移和出段三行模板分别在自己的高低层生成，坡道专用断面再从低端衔接。正反向使用对称的低侧规则，不会把 Railcraft 上坡轨道与水平弯轨合并。
- 全部坡步现在一次性与可用直线边做全局匹配，而不再逐个贪心移动。相邻坡步的路线索引间距不小于 `ceil(1 / maximumGrade)`；默认最大坡度 10% 时至少间隔 10 格。这避免某个理论坡步跨过连续曲线模板后，与下一坡步挤在同一小段内。
- 隧道各横向格的楼层不再直接继承方格中心点的 Y，而是由每个坡道低端处的解析切线断面划分：以单位切线的点积判定格子位于高侧、低侧或坡道断面内。高低层分界因此是当前曲线切线的垂线，并以 Minecraft 方格阶梯逼近，不会在弯道中退化为固定 X/Z 行。
- 坡道专用七格断面沿上述解析法线逐格取整，取整前以法线两个分量中的较大绝对值缩放到 1，保证从 `-3..3` 的每个横向序号都对应唯一方块。因此接近 45° 的坡道不会因单位法线取整重复而把七格断面压缩成五格。曲线坡道两侧墙柱可位于不同的线路纵向坐标，但都使用三格高垂直强化混凝土台阶；接触网凹槽和最外顶板沿同一法线整体抬高一层。直线坡道是该规则的法线恰好平行 X/Z 轴时的特例，既有断面保持不变。
- 坡道解析法线中的五格净空是 `GradeLayout` 的权威低层断面，平台等设施与净空、道床使用同一归层结果；中央三格 `43:8` 也会在统一外壳生成前直接并入最终语义。同一 XZ 若被相邻高端断面误分配了高一层的设施、道床或净空，则删除高层占位并以坡道低端为准。坡道重放只负责五格净空内的接触网槽，不再强制覆盖法线两端；实际正交墙边界决定垂直台阶，墙后的对角格保持整块强化混凝土背衬。
- 若方格取整曾令上述五格中的边缘格落入相邻高层，坡道墙的第三排垂直台阶会在真实正交墙边界中比较法线端点及其高侧邻格，选择最接近坡步中点的一列；被移走墙列的内侧顶角同时用强化混凝土封闭。该规则使曲线两侧墙顶与平台在同一高低分界换层，不会让第三排台阶单独向低侧偏出一格。
- 坡道与 3×8 弯道过渡重合时，最终阶段会重新应用坡步高侧水平过渡实际拥有的接触网凹槽语义：两侧 subtype1 上台阶和中央空气覆盖坡道及外壳的默认混凝土，但不重放外围混凝土，也不恢复低侧已由坡道专用断面接管的旧凹槽。最终墙列封顶后，其正上方由相邻高层普通断面遗留的低优先级顶板计划会直接删除而不是改写为空气，因此既不会覆盖凹槽台阶，也不会在隧道外生成孤立方块或短条。

## 内置模板与安全

隧道模板和运行限制均定义在 Java 源代码的 `TunnelConfig` 中，不会创建 `tunnel_presets.json`。默认最大坡度为 10%，其他限制为路线长度 2048 格、修改 500,000 个方块、每 tick 处理 4096 个方块；预览有效期为 60 秒。

生成前会向执行指令的玩家持续显示青色隧道外描边和统计，不修改世界。描边由最终方块计划提取，包含弯道扩宽与坡道抬高；可见线较亮，被现有方块遮挡的线较暗，并在 `confirm`、`cancel` 或 60 秒有效期结束时消失。系统按 tick 分批生成并在世界存档中保存最近一次撤销数据，包括 TileEntity NBT。生成途中执行 `cancel` 会自动回滚已修改部分。

## Railcraft 依赖

Railcraft 是必需依赖。隧道代码通过 Forge 注册表查找 Railcraft 方块，不直接引用 Railcraft Java 类。相邻 Railcraft 源码当前注册的强化轨道 ID 是 `railcraft:track_flex_reinforced`。

开发环境通过 `META-INF/nebulaecraft_at.cfg` 同步公开 Railcraft 所需的 `TileEntity.REGISTRY` 和 `NBTTagList.tagList`。这是因为 ForgeGradle 3 的反混淆运行环境会读取 `run/mods` 中外部 Railcraft JAR 的 Access Transformer，却不会把这些 SRG 字段规则提前应用到开发用 Minecraft 依赖；发布 JAR 清单也包含同一 `FMLAT` 声明。

本项目使用的 ForgeGradle 3 旧版 1.12 管线在 AT 内容变化后可能把仍含 `Side.BUKKIT` 的 joined 中间包放进 `runClient`/`runServer` 类路径，导致 `NetworkRegistry.newChannel` 在模组构造阶段空指针。`prepareDevForgeJar` 会从正确的 `-recomp.jar` 生成项目本地副本，使用 `gradle/nebulaecraft_dev_at.cfg` 中的 MCP 字段名应用同样两条规则；两个运行任务会自动使用该副本。此逻辑仅服务开发运行，不进入发布模组。

## 开发记录

以下内容保留自动隧道工具从初版到当前实现的设计、调试和验证历史；若历史描述与前文冲突，以前文的当前功能说明为准。

### 1. 原始需求

参考 `docs/2026-07-26 15-04-04.mp4`，新增类似 WorldEdit 的隧道自动生成工具：玩家使用工具依次选择两个带方向的标记方块，再通过指令预览和确认生成一条圆滑、曲率缓和的地铁隧道。

确定的注册 ID：

- 标记方块：`nebulaecraft:autogen_marker`
- 选择工具：`nebulaecraft:autogen_wand`

允许使用项目现有 `RegistryHandler` 注册上述方块和物品。

### 2. 路线、交互与指令

- 标记方块使用可旋转箭头表达端点方向；空手右键旋转。
- 标记方块的选择与碰撞范围取自实际模型原始范围 `X 7..9、Y 0..13.5、Z 1.5..9`，并按四个 `FACING` 分别旋转。
- 魔杖依次右键记录起点与终点，选区按玩家保存；两个箭头必须相向。
- 标记坐标代表中央道床位置，生成时被道床替换，撤销时恢复。
- 路线使用五次 Hermite 曲线，端点保持零曲率及零坡度变化。
- 默认最小半径 12 格、最大坡度 10%。
- 默认最长路线 2048 格、最多修改 500,000 个方块、每 tick 修改 4096 个方块。
- 预览有效期 60 秒；全服同一时间只运行一个生成或撤销任务。
- 最近一次生成保存原方块状态和 TileEntity NBT，可在取消、服务器中断或执行撤销时分批恢复。

指令：

```text
/nebulaetunnel preview <preset> <platformColor> <power> [mirror]
/nebulaetunnel confirm
/nebulaetunnel cancel
/nebulaetunnel status
/nebulaetunnel undo
/nebulaetunnel clear
```

别名为 `/ntunnel`，权限等级为 2。供电方式包括：

- `none`
- `catenary`
- `thirdrail_white`
- `thirdrail_yellow`

### 3. 材料约定

- 整块衬砌：Railcraft `railcraft:reinforced_concrete` meta 8（light gray）。
- 水平台阶：`nebulaecraft:reinforced_concrete_slab` subtype1。
- 垂直台阶：`nebulaecraft:reinforced_concrete_vertical_slab`。
- 中央道床：旧 ID `43:8`，即 `minecraft:double_stone_slab` meta 8。
- 两侧道床：旧 ID `44:0`，即 `minecraft:stone_slab` meta 0。
- 强化轨道：`railcraft:track_flex_reinforced`；方块解析仍兼容旧 ID `railcraft:reinforced_track` 和 `railcraft:track_reinforced`。
- 金属平台：`railcraft:post_metal_platform`，颜色由指令决定。
- 接触网模式：使用 NebulaeCraft 钢性接触网系列，而非柔性接触线系列。
- 默认平台位于线路左侧、第三轨位于右侧；`mirror` 同时交换两者。

### 4. 最终直线断面

标记所在中央道床为 Y=0。断面固定为 7×7，从上到下为：

```text
强化混凝土 × 7
强化混凝土 × 2 | subtype1上台阶 | 钢性接触网 | subtype1上台阶 | 强化混凝土 × 2
强化混凝土 | 空气 × 5 | 强化混凝土
垂直强化混凝土台阶 | 空气 × 5 | 垂直强化混凝土台阶
垂直强化混凝土台阶 | 空气 × 5 | 垂直强化混凝土台阶
强化混凝土 | 空气 × 2 | 强化轨道 | 空气 × 2 | 强化混凝土
强化混凝土 × 2 | 44:0 | 43:8 | 44:0 | 强化混凝土 × 2
```

平台、第三轨和灯具是设施覆盖层，会占用相应净空格，但不再替换结构衬砌。金属平台放在完整左侧基础方块上方。

### 5. 旋转方块方向修正

调试时确认 NebulaeCraft 多个带旋转功能方块的子 ID 与原版水平 metadata 规则不同，不能直接假定 `EnumFacing` 的原版序号。

生成器改为显式使用本模组的模型状态映射：

```text
NORTH = 0
SOUTH = 1
WEST  = 2
EAST  = 3
```

并按各模型的实际语义分别处理：

- 垂直台阶和隧道灯：状态表示模型朝向净空，实体贴在相反侧。
- 第三轨直线：`facing` 表示导电轨位于当前方块的哪一侧，不表示线路前进方向。
- 第三轨坡道：结合导电轨所在侧和真实上升方向选择 `slope_1` / `slope_2`。
- 第三轨弯道：根据第三轨处于曲线内侧还是外侧选择 `diagonal_2` / `diagonal_1`，再按实际拐角设置方向。
- 第三轨坡道只替换实际坡轨所在的低端切面，高端相邻平轨恢复普通第三轨。
- 第三轨在有效长度索引 `0, 3, 6...` 使用对应颜色的支架模型；直线使用 `*_support`，弯道使用 `*_support_diagonal`，坡道因没有专用支架模型而保留坡道。
- 单格横移时，第三轨斜线对固定依次使用 `diagonal_1、diagonal_2`。`diagonal_1` 锚定在首个轨道转角的前一索引；`diagonal_2` 使用首个转角索引的模型状态，实际位置同时沿入口反方向和横移方向各移动一格，从而落在 `diagonal_1` 的横向相邻空气格，并位于第一格出段直线第三轨的纵向相邻格。`diagonal_1` 使用首个转角方向的反向，`diagonal_2` 使用第二个转角的原始方向，不能共用同一套 180° 修正。斜线支架仅能替换 `diagonal_1`。
- 支架有效长度计数会把相邻的一组 `diagonal_1 + diagonal_2` 合并为一格；连续 45° 斜线路段拆成首尾相接的单格横移单元，每个单元使用与已验证单格偏移相同的位置和朝向，不再让中间单元退回普通转角逻辑，也不生成额外直线格。
- 钢性接触网坡线：按真实上升方向设置。
- 钢性接触网斜线：按路径前后连接形成的拐角设置。
- Railcraft 强化轨道继续使用其 `EnumRailDirection` metadata。
- Railcraft 弹性轨道的 `onBlockAdded` 会在首次写入时根据当时已存在的邻轨重新计算形状。分批顺序生成时，弯轨的后一格尚不存在，显式设置的转角可能被改回直轨；生成计划现于全部结构操作之后追加轨道定向复写，复写不重复采集撤销数据。

### 6. 隧道灯规则

最初实现为每 8 格在左右墙轮流设置一盏灯。后续修正为：

- 所有灯具均集中在金属平台一侧。
- `lightSpacing` 直接作为路线索引周期；默认值 9 对应索引 `0, 9, 18...`，两盏灯之间保留 8 格。
- 使用 `mirror` 时，平台和全部灯具同步换边。

### 7. 弯道完整断面过渡

方格化平滑曲线的一格横向换位会形成两个相邻轨道拐角。直接叠加两个普通 7 格断面会导致道床互相覆盖、内部残留墙柱以及洞体收窄。

金属平台不跟随两个相邻弯轨硬连接成连续面。朝平台侧换位时，删除旧侧末端两格并在新侧提前补一格，使两段平台只保持对角相邻；背离平台侧换位时执行纵向镜像规则，`mirror` 后同样成立。

最终实现为旋转适配四个方向的 3×8 完整断面过渡。最底层沿换位方向的三行依次为：

```text
CC | 44 | 43 | 44 | 44 | CC
CC | 44 | 43 | 43 | 44 | CC
CC | 44 | 44 | 43 | 44 | CC
```

其中 `CC` 表示两格强化混凝土。其余各层按同一规律同步调整：

- 顶板三行均扩宽为 8 格强化混凝土。
- 普通净空层变为两侧外墙包围 6 格净空。
- 明确清除两个旧断面重叠后位于内部的墙块。
- 两层垂直台阶移动至过渡区的新外缘。
- 接触网槽按 `1格 → 2格 → 1格` 横向换位。
- subtype1 上台阶按与 `44:0` 相同的规律补齐。
- 两个中央道床上分别保留 Railcraft 强化弯轨。
- 平台、第三轨、接触网和灯具优先级高于结构清空操作，不会被过渡模板误删。
- 接触网支撑间隔命中斜线时不再覆盖斜线模型，而是在前后两格内寻找最近的水平直线格；等距时固定优先前一格，四个候选均不符合时忽略本次支撑放置。
- 隧道灯命中扩宽过渡的内缩半区时向平台侧外移一格，贴合实际外墙。
- 初版曾按每个三行过渡的固定坐标补完整 7 格竖列；长弯道中这些局部接缝彼此重叠，竖列会落入净空或在墙外形成凸块。后续仅合并重叠单元仍无法处理 90° 中段换轴，内外侧视频显示墙体继续断连且方向转换处出现侵入净空的整列混凝土。
- 墙体先合并整条路线所有普通断面和专用过渡断面的水平净空，统一清除净空内低优先级结构，再从净空的正交邻域生成完整外边界。曾尝试把所有仅对角接触净空的格都补成完整强化混凝土列，实际会在曲线内侧的每次横移处形成连续立柱并挤占视觉净空。进一步排查发现，正交边界中同时邻接两个净空格的内侧接缝也曾被当作混凝土角柱，从而替换正常垂直台阶；现在这类墙格优先保留普通断面或 3×8 模板已有的台阶朝向，不再生成整列混凝土。
- 90° 弯道的断面轴切换后，格化过渡的 `shift` 会由指向弯道内侧变为指向外侧；继续固定使用 `projectedOldCenter - 3×shift + incoming` 会把后半段背衬镜像到隧道内。现在通过过渡前后各 4–12 格的平衡窗口计算平滑路线曲率：`shift` 指向内侧时使用外侧出段接缝，`shift` 指向外侧时改用外侧入段接缝。多尺度曲率冲突或全为零时不生成可选背衬。候选格还会对最终合并净空做校验，并以低于所有正常断面结构的优先级写入。
- 后续大半径 90° 弯道实测发现，上述按真实曲率只保留物理外圈背衬的做法会令另一侧的内圈对角接缝完全缺失。现改为只恢复每个 3×8 过渡模板的两个精确接缝候选：入段 `before + 4×shift - incoming` 与出段 `projectedOldCenter - 3×shift + incoming`。两者都必须通过最终合并净空及其正交邻域校验，并继续以最低结构优先级写入；这会同时封闭内外圈，又不会恢复“全部对角邻格补整列”所造成的净空立柱。
- 90° 弯道中部会发生断面主轴由 X 到 Z（或反向）的切换。相邻索引若同时被识别为两套互相垂直的一格横移，只采用先到的一套模板，避免同一轨道转角被重复扩宽；统一外轮廓负责封闭两侧及中段，路线首尾仍保持开放。
- 仅去重结构模板会连同后到的新轴墙面朝向一起丢弃；统一外轮廓又会无条件保留先到模板已有的垂直台阶，使换轴中心整段偏向旧轴。现在去重时额外记录旧轴/新轴模板对，但仍只生成一套结构；墙面重建阶段沿最终合并净空寻找每行两侧的真实边界，入段采用旧模板的 `before、oldCorner` 两行，出段采用新模板的 `oldCorner、projectedOldCenter` 两行，仅覆盖垂直台阶朝向。这样南北向与东西向各占两行，不依赖 `EnumFacing.HORIZONTALS` 的等距遍历顺序，也不会重新引入两套 3×8 模板互相切割。边界搜索最多前进两个模板半宽之和 `3 + 4 = 7` 格；若该范围仍处于净空就放弃覆盖，避免命中远处无关轮廓。
- 道床改为按轨道路网重建，而非依赖断面主轴：路线格统一恢复 `43:8`，每个格子的前后连接轴分别贡献左右 `44:0` 邻格；坡轨贡献 `43:8`。转角会自然取得两组侧邻格，连续换位与 X/Z 主轴切换处均不会留下断口。全局混凝土地板完成后再次按三行模板恢复过渡区额外的 `44:0`，保留原 3×8 底层连续图案。
- 实机复核发现，上述“四条截面射线”虽然写入结果在统计上是旧轴 4 格、新轴 4 格，却只命中了两条阶梯墙的远端；中间可见墙格仍继承旧模板，视觉上依然集中为一个方向。现在改为按线路逻辑左右侧分别配对旧、新墙锚，对最终外轮廓执行局部 8 邻接寻路，并覆盖路径上的全部垂直台阶。分配器只使用该墙格实际邻接净空的法线，在每侧将旧、新朝向分成相等数量，奇数格最多相差一格，从几何上避免台阶半砖朝向无净空方向而贴近 `44:0` 边缘。
- 同次实机检查还发现，真正与 `44:0` 共用 XZ 的是金属平台而非垂直台阶。根因是结构换轴会去重第二套模板，同时也漏掉了它的平台调整；相邻普通斜线单元的锚点之间也可能残留旧平台。现在结构模板仍去重，但全部设施过渡都保留：先清除最终 `43:8/44:0` 上方的平台，再检查相邻平台锚点是否已经通过现有平台 8 邻接连通，仅对断开的分量补斜线桥；随后将有效平台格及补桥的对角内肘并入净空、重建墙和完整混凝土基层。连通检查避免在轴切后的正常平台侧额外生成平行格。
- 道床进一步提前为独立的 `TrackbedLayout`：路网邻格与 3×8 模板附加格在墙面生成前合并，统一作为平台禁占区及净空不变量；不再在墙面完成后才补写过渡道床。
- 半径 100 的 E→N 实测路线暴露出换轴去重仍有方向不对称：相邻的旧轴、新轴候选中，新轴候选虽然继续参与平台修正，却没有进入 `TrackbedLayout`、普通净空和接触网凹槽。结果新轴方向应为 `44:0` 和混凝土缓冲的两列被旧轴垂直台阶墙占据。现在完整七层模板仍只使用去重后的候选，但道床和接触网凹槽按全部候选执行带优先级的语义合并；其中接触网行保持“中央空气高于两侧 subtype1、两侧 subtype1 高于外围混凝土”的覆盖关系，不会覆盖优先级更高的实际接触网。
- 最终 `TrackbedLayout` 的每个 `43:8/44:0` 格向四个水平方向扩张一格后再参与净空与墙边界提取，路线开放端之外除外。这显式保证道床与任何非端部墙格都至少隔着一格完整混凝土地板。半径 100 路线中，原先侵入的 `(-1409,6,-266)` 恢复为 `44:0`，`(-1408,6,-266)` 成为混凝土地板及上方净空，墙退至 `x=-1407`。
- 同一路线有 7 盏灯因旧逻辑只检查命中的第一个过渡、且最多外移一格而浮空，其中两盏实际需要外移两格。灯具改为在全部结构和设施确定最终净空后放置：从轨道格沿平台侧扫描到净空边界，选择墙前最后一个净空格，因此不再依赖某个局部过渡模板或固定外移量。

### 8. 坡道专用断面

- 顶板相对道床抬高至第 8 层。

- 预览从一次性中心线粒子改为客户端持久线框。服务端从最终计划的实体方块列中提取每个解析切线断面的左右外墙上下角，客户端连接四条纵向外边并每 8 格补一个断面环；参考 WorldEditCUI 的双深度通道画法，可见线使用高亮青色，遮挡线使用低透明度暗青色。线框仅发送给预览发起者，并随 `confirm`、`cancel` 或有效期到期清除。

### 9. 崩溃排查

首次进入世界时，`crash-2026-07-26_16.41.04-server.txt` 显示 Railcraft 在反序列化进度条件时读取 `TileEntity.REGISTRY`，触发 `IllegalAccessError`。

最终处理：

- 新增 `META-INF/nebulaecraft_at.cfg`。
- 公开 `net.minecraft.tileentity.TileEntity field_190562_f`（`REGISTRY`）。
- 在 ForgeGradle 配置和 JAR manifest 中声明该 Access Transformer。
- 删除 `RegistryHandler` 中引用客户端专用字段的调试输出，避免独立服务端加载失败。

随后进入包含 Railcraft 箱子矿车的世界时，列车存档读取又因访问 `NBTTagList.tagList` 触发 `IllegalAccessError`（`crash-2026-07-26_17.40.18-server.txt`）。因此最终 AT 文件同步 Railcraft 当前实际触发的两条必要规则：

- `TileEntity.REGISTRY`
- `NBTTagList.tagList`

未把 Railcraft AT 中其余尚未触发的字段规则无差别复制进项目。

补充处理 ForgeGradle 3 开发运行缓存问题：增加 `prepareDevForgeJar`，从不含 `Side.BUKKIT` 的 `-recomp.jar` 生成带两条 MCP 名访问规则的本地开发副本，并在 `runClient`、`runServer` 启动前自动替换 joined 中间包。否则新增第二条 AT 后会在进入主菜单前先于世界加载触发 `NetworkRegistry.newChannel` 空指针，这不是隧道或 Railcraft 存档逻辑本身的异常。
